# SecretShelf — памятка для сессий

Устройство и решения — в README.md. Здесь только то, что легко сломать.

- **Окна при проверке не показывать.** Шторка — окно поверх всех у правого края, оно
  закроет работу владельца. Вид проверять отрисовкой в PNG без показа окна: образец —
  `D:\tmp\secretshelf-render-harness\Program.cs` (создаёт `DrawerWindow`, снимает
  `Content`, рендерит через `RenderTargetBitmap`). Перетаскивание, анимацию и буфер
  обмена так не проверить — это делает владелец руками.
- **Буфер обмена владельца не трогать** в автоматических проверках.
- **Настоящее хранилище** `%APPDATA%\SecretShelf\vault.kdbx` — не открывать, не копировать,
  не удалять. Для проверок — временный файл с тестовыми данными.
- **vendor/KeePassLib правим минимально**, каждую правку помечаем `// SecretShelf` и
  вносим в README: иначе обновление ядра превратится в раскопки.
- **Секретные значения в модели не держать.** `VaultField` — без значения; значение берётся
  `Vault.GetValue` в момент показа или копирования.
- **Заход 3 (MCP):** агент работает ссылками на секреты, значений в ответах инструментов
  нет (кроме полей с `FieldAccess.Reveal` и `take_temp_secret`). По умолчанию — подтверждение
  каждого запроса в шторке. Подключение сервера к агентам — только с явного «да» владельца.
- **Шторка не обязательна для агентов** (решение владельца 29.10.2026): она — место обмена
  ключами между ним и агентами, а не единственный путь к ключам. Главный инструмент —
  временный секрет (`TempSecret`, верхняя строка): одна передача, только в памяти, стирается
  при первом использовании и при блокировке, без окон подтверждения. Положенное агентом
  забирает только владелец.
- `dotnet` из Git Bash: полный путь `"/c/Program Files/dotnet/dotnet.exe"`; из длинных
  путей временных каталогов не запускается — работать в `D:\tmp`.
- **Автозапуск пишет в реестр** (HKCU\...\Run) при первом запуске приложения. Проверочная
  отрисовка не вызывает `Loaded`, поэтому реестр, трей и горячую клавишу не трогает —
  так и держать: не вызывать в ней `Expand`/`OpenSettings` (они показывают окно).
- **Release-exe занят, пока шторка запущена у владельца.** Его процесс не гасить —
  попросить выйти (шестерёнка → «Выйти из SecretShelf», или меню значка в трее).
- **MCP-сервер подключён к Claude Code и Codex** (область user у Claude — `~/.claude.json`,
  у Codex — `[mcp_servers.secretshelf]` в `~/.codex/config.toml`). Каждая версия выкладывается
  в свою папку: `dotnet publish src/SecretShelf.Mcp -c Release -o dist/mcp-ГГГГ-ММ-ДД`, затем
  путь меняется в обоих конфигах (с копиями). Перезаписывать работающую папку нельзя: exe
  держат открытые сессии агентов, их процессы не гасить. Старые папки удалять только с
  согласия владельца, когда сессии на них закрыты. Действующая — `dist\mcp-2026-10-29\`.
- **Скилл** — исходник `docs/agents/secretshelf/SKILL.md`, копии в `~/.claude/skills/secretshelf/`
  и `~/.codex/skills/secretshelf/`; поменял исходник — обновить обе копии.
