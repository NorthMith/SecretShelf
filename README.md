# SecretShelf

Шторка у правого края экрана Windows для логинов, паролей, API-ключей, SSH-ключей —
любых записей «название + N полей». Хранилище — файл KDBX 4 (формат KeePass):
открывается также в KeePass / KeePassXC, это запасной выход.

## Запуск

```
dotnet build src/SecretShelf.App -c Release
src\SecretShelf.App\bin\Release\net8.0-windows10.0.19041.0\SecretShelf.exe
```

Нужен .NET 8 SDK. Хранилище по умолчанию: `%APPDATA%\SecretShelf\vault.kdbx`,
резервные копии — `%APPDATA%\SecretShelf\backups\` (перед перезаписью, не чаще раза в 10 мин, последние 30).

## Устройство

| Каталог | Что |
|---|---|
| `vendor/KeePassLib` | Ядро KeePass 2.61.1 (GPLv2), собранное под .NET 8. Правки — ниже |
| `src/SecretShelf.Core` | `Vault`: записи, поля, порядок, сохранение, копии |
| `src/SecretShelf.App` | WPF: шторка, язычок, буфер обмена |
| `tests/SecretShelf.Core.Tests` | xUnit: круговое сохранение, порядок, пароль, копии, замер KDF |

### Раскладка в KDBX
- запись = `PwEntry` в корневой группе; порядок записей = порядок в группе;
- значения полей — строки записи; секретные — `ProtectedString` (зашифрованы в памяти);
- первое открытое поле ложится в `UserName`, первое секретное — в `Password`
  (видно в стандартных колонках KeePass), остальные — под своими названиями;
- порядок полей, подписи и уровень доступа для ИИ — JSON в `CustomData["SecretShelf.Fields"]`.

### Шифрование
KDBX 4: AES-256, ключ из пароля — Argon2id (64 МиБ, 2 потока), итерации подбираются
при создании под ~0,4 с на этой машине. KeePassLib при каждом сохранении заново считает
Argon2 с новой солью, поэтому сохранение идёт в фоне через 0,7 с после последней правки.

### Быстрый вход
`%APPDATA%\SecretShelf\quick-unlock.json` хранит мастер-пароль, зашифрованный для быстрого
входа. Снаружи всегда DPAPI (только эта учётная запись Windows), внутри для Hello и ПИН —
AES-256-GCM: ключ из подписи Windows Hello (RSA PKCS#1 v1.5 детерминирована, проверяется при
включении) или из ПИН-кода через Argon2id (32 МиБ). 5 неверных ПИН подряд — файл стирается.
Смена мастер-пароля сбрасывает быстрый вход, выключение способа стирает файл.
Приложение собирается под `net8.0-windows10.0.19041.0` ради API Windows Hello.

### Память
Argon2 на каждом открытии и сохранении берёт 64 МиБ; сборщик мусора сам их системе не
отдаёт. Замер 27.10.2026: 143 МБ частной памяти после открытия, 12 МБ после принудительной
сборки с уплотнением — поэтому `Vault` вызывает её после каждого подсчёта ключа.

### Правки в vendor/KeePassLib
- `Net8Compat/ProtectedMemoryShim.cs` — замена `ProtectedMemory` (нет в .NET 8)
  на тот же `CryptProtectMemory`, что был под ним в .NET Framework;
- `Serialization/FileTransactionEx.cs` — две строки: `File.Get/SetAccessControl` →
  `FileInfo.Get/SetAccessControl` (помечены `// SecretShelf`).

Исходный архив: `KeePass-2.61.1-Source.zip`, SHA-256
`711BD9EC7076661678469E51BAE876DEBAC07A08C32F1B1C6B3B8FE5E761C13A` сверен с keepass.info.

## Лицензия
Из-за KeePassLib приложение — производная GPLv2: для себя без ограничений,
при распространении нужно открывать исходники.

## Этапы
1. ✅ Шторка, список с перетаскиванием, записи с N полями, пароль, копирование с очисткой буфера.
2. Часть 1 ✅ — экран настроек, значок в трее, горячая клавиша (по умолчанию Ctrl+Alt+P),
   автоблокировка (бездействие системы, Win+L, сон), смена мастер-пароля, запуск с Windows,
   возврат памяти после Argon2 (было ~340 МБ на процесс).
   Часть 2 ✅ — быстрый вход поверх мастер-пароля (Windows Hello, ПИН, без пароля; мастер-пароль
   раз в N дней), импорт CSV из Chrome/Edge/Firefox с отсевом дублей и удалением файла.
3. ✅ MCP-сервер для ИИ-агентов: уровни доступа полей, подстановка без раскрытия, окно подтверждения.
   Осталось: подключить к клиентам (Claude Code, Codex, программа для DeepSeek) и поставить скилл.

## ИИ-агенты (MCP)

```
агент (Claude Code, Codex, …) ──stdio/MCP──> SecretShelf.Mcp.exe ──named pipe──> шторка ──> хранилище
```

- **У MCP-сервера ключей нет.** Он передаёт запросы шторке по каналу
  `SecretShelf.Agents.<SID пользователя>`: доступ только у текущего пользователя Windows,
  сетевые подключения запрещены. Шторка не запущена или заперта — агент получает понятный отказ.
- **Уровни доступа поля** («⋯» у поля → «Доступ для ИИ»): Закрыто (по умолчанию) /
  Видно название / Подстановка / Открыто, плюс галочка «Без подтверждения» и список
  разрешённых программ (`file` — запись в файл).
- **Подтверждение** — отдельное окно у правого нижнего угла, 60 с без ответа — отказ.
  Добавление нового ключа, поиск по папкам и удаление спрашивают всегда.
- **Инструменты:** `list_secrets`, `get_secret_value`, `run_with_secrets`, `write_secret_file`,
  `store_secret`, `delete_secret`, `scan_for_secrets`. Значения агенту не возвращаются (кроме
  «Открыто»); вывод программ маскируется (только точное совпадение значения).
- **Не трогается никогда:** учётные данные ИИ-клиентов (`~/.claude`, `~/.codex`, … — кроме
  `~/.claude/hub`), само хранилище, файл быстрого входа.
- **Журнал** запросов без значений: `%APPDATA%\SecretShelf\agent-log.jsonl`, последние — в настройках.
- **Инструкция для агентов:** `docs/agents/secretshelf/SKILL.md` (черновик скилла; для Codex и
  других — тот же текст в их файл инструкций).
- **Проверка:** `tests/…/AgentGatewayTests.cs` (16 тестов) и сквозной прогон настоящего
  `SecretShelf.Mcp.exe` по протоколу MCP на временном хранилище (`D:\tmp\secretshelf-mcp-smoke`).

Сборка сервера: `dotnet build src/SecretShelf.Mcp -c Release` →
`src\SecretShelf.Mcp\bin\Release\net8.0-windows\SecretShelf.Mcp.exe`.
