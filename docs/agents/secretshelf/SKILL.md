# SecretShelf: ключи владельца без раскрытия значений

Ключи владельца лежат в шторке SecretShelf. Ты работаешь с ними через MCP-сервер
`secretshelf` и **не видишь значений**: шторка подставляет их сама, а ты получаешь
только результат. Так ключи не попадают в переписку.

## Главные правила

1. **Никогда не проси владельца прислать ключ в чат** и не выводи значения: ни в ответе,
   ни в командах, ни в файлах, которые потом читаешь. Нужен ключ — используй инструменты ниже.
2. **Не читай файлы с ключами сам** (`.env`, `~/.ssh/id_*`, конфиги с токенами), чтобы
   «посмотреть, что там». Их содержимое уйдёт в переписку. Для переноса в шторку —
   `store_secret`, для описи — `scan_for_secrets`.
3. **Ссылайся на ключ как «Запись / Поле»** — по названиям из `list_secrets`.
4. **Различай, кто отказал.**
   - **Владелец** (ответ «Владелец отказал в доступе»: он нажал «Отказать» или не ответил
     60 секунд) — окончательно. Не повторяй, пока он сам не попросит; скажи ему и спроси, как быть.
   - **Правило шторки** (ответ называет причину: уровень доступа, программа не в списке,
     запрещённый файл, заперто) — это сведения, а не запрет на работу. Перескажи владельцу
     причину. Когда он её устранил (открыл доступ, обновил шторку, отпер) и просит повторить —
     **повтори тот же вызов SecretShelf**. Это не обход.
   - **Обход** — это достать ключ мимо шторки: прочитать файл, вывести значение, взять другой
     программой. Он запрещён всегда. Повтор того же инструмента SecretShelf обходом не бывает.
5. **Добавлять, заменять и удалять ключи — только по просьбе владельца.** Удаление всегда
   спрашивает подтверждение, это нормально.

## Инструменты

| Инструмент | Когда |
|---|---|
| `list_secrets` | Первым делом: какие записи и поля тебе открыты и с каким уровнем |
| `get_secret_value` | Только поля уровня «Открыто» (логин, адрес сервера) |
| `run_with_secrets` | Запустить программу с ключом в переменной окружения или на стандартном вводе |
| `write_secret_file` | Записать `.env` или конфиг по шаблону `{{Запись/Поле}}` |
| `store_secret` | Положить ключ в шторку из файла, из `.env` или из вывода программы |
| `delete_secret` | Убрать поле или запись (по просьбе владельца) |
| `scan_for_secrets` | Найти, где лежат ключи в папке: пути и имена, без значений |

Уровни доступа полей (их ставит владелец): «Видно название» — знаешь о поле, взять не
можешь; «Подстановка» — можно подставлять в команды и файлы; «Открыто» — можно получить
значение. Закрытые поля тебе не видны совсем.

## Как подставлять ключ

`run_with_secrets` запускает программу **без командной оболочки**: аргументы — отдельными
элементами, `$VAR` и `%VAR%` в аргументах не раскрываются. Значит:

- **Программа сама читает переменную окружения** — лучший вариант:
  `command: "python", args: ["script.py"], env: [{name: "ANTHROPIC_API_KEY", entry: "API A", field: "Ключ API"}]`.
- **curl** — заголовок со стандартного ввода, ключ не попадёт в список процессов:
  `command: "curl", args: ["-s", "-H", "@-", "https://api.example.com/v1/models"],
  stdin_template: "Authorization: Bearer {{API A/Ключ API}}"`.
- **ssh с ключом из шторки**: запиши ключ во временный файл через `write_secret_file`
  (`C:\Users\<user>\.ssh\<имя>`, права ставятся только на текущего пользователя) и укажи его в `-i`.
  Файл потом не удаляй сам — спроси владельца.

Вывод программы возвращается с ключами, заменёнными на `***`. Маскировка ловит только
точное значение: не печатай ключ в перекодированном виде и не пытайся его извлечь.

## Как перенести ключи владельца в шторку

1. Спроси владельца, **какие папки смотреть и какие пропустить** (у него есть рабочие
   каталоги с чувствительным содержимым).
2. `scan_for_secrets` по каждой согласованной папке — получишь пути и имена переменных.
3. Покажи владельцу список и предложи названия записей («Сервис / Поле»).
4. После его «да» — `store_secret` для каждого: `source: "env_file"` + `variable` для `.env`,
   `source: "file"` для файлов ключей. Старые файлы не трогай: что с ними делать, решает владелец.

Учётные данные самих ИИ-клиентов (`~/.claude/.credentials.json` и подобные) шторка не
трогает никогда — и ты не пытайся.

## Если что-то не так

- «SecretShelf не запущен» — попроси владельца запустить шторку.
- «Хранилище заблокировано» — попроси открыть шторку и повтори запрос.
- «Поля нет среди доступных» — проверь `list_secrets`; возможно, владелец не открыл поле:
  скажи ему, какое поле и какой уровень нужен («⋯» у поля → «Доступ для ИИ»).
