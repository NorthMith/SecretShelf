# SecretShelf: передача ключей между владельцем и агентом

Шторка SecretShelf — хранилище паролей владельца и защищённое место для передачи ключей
между ним и тобой, чтобы значения не ходили через чат. **Это не обязательный путь**: с
ключами работай как обычно — по указанию владельца бери их, откуда он скажет, и вписывай,
куда нужно. Шторка — когда владелец о ней говорит.

## Временный секрет — одна передача

Верхняя строка шторки. Живёт до первого использования, на диск не пишется, при блокировке
шторки пропадает. Подтверждений нет.

**Владелец → тебе.** Он вставил значение и говорит «взял из шторки» / «во временном лежит».

- **По умолчанию подставляй не глядя** — так значение не попадает в переписку:
  - в файл: `write_secret_file` с шаблоном, где ключ — `{{Временный}}`
    (например `.env`: `DEEPSEEK_API_KEY={{Временный}}`);
  - в программу: `run_with_secrets` с `env: [{name: "API_KEY", temp: true}]` или
    `stdin_template: "Authorization: Bearer {{Временный}}"`.
- `take_temp_secret` возвращает само значение — только когда без этого нельзя (например,
  ключ надо вписать в чужой интерфейс) или владелец попросил. Прочитанное уходит в журналы
  API так же, как вставленное в чат.
- После любого из этих вызовов временный секрет стёрт. Нужен второй раз — попроси владельца
  вставить снова.

**Ты → владельцу.** `put_temp_secret`: из файла (`source: "file"`), строки `.env`
(`source: "env_file"`, `variable`) или вывода программы (`source: "command"`). Значение в
переписку не идёт. Скажи владельцу: «положил во временный секрет шторки». Он скопирует —
секрет сотрётся.

## Постоянные записи шторки

По просьбе владельца: `list_secrets` — что есть; подставить — `run_with_secrets` /
`write_secret_file` со ссылкой `{{Запись/Поле}}`; сохранить — `store_secret`; убрать —
`delete_secret`; найти, где на диске лежат ключи (пути и имена, без значений), —
`scan_for_secrets`. У записей есть уровни доступа и окна подтверждения — это нормально.

- Владелец нажал «Отказать» — окончательно, пока он сам не попросит снова.
- Отказ по правилу шторки (уровень доступа, программа не в списке) — перескажи причину.
  Владелец устранил и просит повторить — повтори тот же вызов.
- «SecretShelf не запущен» / «заблокировано» — попроси владельца открыть шторку.

## Как подставлять

`run_with_secrets` запускает программу **без командной оболочки**: аргументы — отдельными
элементами, `$VAR` и `%VAR%` не раскрываются. Лучше всего — программа сама читает
переменную окружения; для curl — заголовок со стандартного ввода (`-H @-`). Вывод
возвращается с подставленными значениями, заменёнными на `***`.

`write_secret_file` пишет файл **целиком** по шаблону (прежний сохраняется рядом как
`.bak-…`). Конфиг уже есть — собери шаблон из его содержимого плюс ссылка на месте ключа.
Файл в git-репозитории — до записи проверь, что он в `.gitignore`.

Учётные данные самих ИИ-клиентов (`~/.claude/.credentials.json`, `~/.codex/auth.json`)
шторка не трогает никогда — и ты не пытайся.
